## 🔴 架构偏差与问题

### 1. TUI 说明书缺失

**问题**: Go AI服务无TUI说明书

**影响**:
- 用户双击AI服务二进制时，直接启动HTTP服务
- 无使用说明，不符合用户体验预期

**解决方案**:
```bash
# 预期行为
$ ./pixly-ai-service
# 应显示:
# ┌────────────────────────────────────┐
# │  Pixly AI 预测服务                 │
# │  智能参数优化 • 质量评估            │
# ├────────────────────────────────────┤
# │  启动: ./pixly-ai-service --start   │
# │  端口: 50052                        │
# └────────────────────────────────────┘
```

### 2. Python ML系统集成不清晰

**问题**: 
- Python训练脚本分散在 `tools/` 和 `training/`
- 没有统一的训练入口
- 与Go AI服务的集成机制不明确

**影响**:
- 难以验证机器学习功能是否完整
- 训练流程不清晰
- 可能存在未使用的代码

**建议**:
1. 创建 `core/python/` 目录
2. 统一训练脚本入口
3. 编写训练流程文档
4. 验证与Go服务的集成

### 3. 历史债务 - JS层CLI Fallback

**问题**: 
- `plugin/js/plugin-modules/04-conversion.js` 包含CLI fallback代码
- 违反架构原则（UI层不应实现转换逻辑）

**状态**: 
- ⏳ 低优先级（插件可选）
- 📋 已记录在 `ARCHITECTURE_ANALYSIS_AND_TODO.md`

### 4. 命名混淆

**问题**:
- `cmd/rust-service/main.go` 是Go代码，不是Rust
- 历史遗留命名

**影响**: 轻微（仅混淆）
