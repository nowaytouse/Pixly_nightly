## 🔍 发现的问题

### 表面问题
- 用1800个样本训练的LightGBM模型R²分数为负（-0.02 ~ -0.8）
- 训练数据收集脚本无法提取特征

### 深度分析（遵循质量宣言的批判性思维原则）

**5 Whys分析**:
1. **Why R²为负？**
   - 模型预测的方差比目标变量的方差还大
   - 模型在"瞎猜"

2. **Why模型瞎猜？**
   - 训练数据中quality/effort只有几个离散值
   - 目标变量方差极小（几乎是常数）

3. **Why目标变量是常数？**
   - 我们用固定参数组合收集数据
   - quality: [60, 70, 80, 90]
   - effort: [4, 6, 8]

4. **Why用固定参数？**
   - 误解了监督学习的目标
   - 以为是学习"特征+参数 → 输出质量"

5. **Why误解？**
   - 没有明确区分：
     - 回归问题：预测连续值（如文件大小）
     - 推荐问题：选择最佳参数组合

### 根本问题

**错误理解**:
```
输入: 图像特征 + 参数(quality, effort)
输出: 文件大小、SSIM质量
目标: 学习"特征+参数 → 输出"的映射
```

**正确理解**:
```
输入: 图像特征
输出: 最佳参数(quality, effort)
目标: 学习"特征 → 最佳参数"的映射
```

这是一个**推荐/优化问题**，不是**回归问题**！

## 💡 关键教训

### 1. 批判性思维的重要性

**错误做法**:
- 看到R²为负 → 立即收集更多数据
- 简单归因："数据不够"

**正确做法**:
- 深度分析：5 Whys方法
- 质疑假设：这真的是回归问题吗？
- 验证现状：系统真的不工作吗？

### 2. 真实性原则

**发现**:
- 系统已经在工作（测试验证）
- 不需要"重新训练"
- 需要的是"增量改进"

**避免**:
- 自欺欺人：假装问题很严重
- 推翻重来：浪费已有工作
- 盲目行动：不验证就开始

### 3. 问题定义的重要性

**错误定义**:
- 回归问题：特征+参数 → 输出质量

**正确定义**:
- 推荐问题：特征 → 最佳参数

**影响**:
- 错误定义导致完全错误的方法
- 浪费大量时间收集无用数据
- 模型永远无法学习

### 4. 遵循质量宣言

**应用的原则**:
- ✅ 批判性思维与深度调查
- ✅ 真实性原则（验证系统状态）
- ✅ 质疑一切表面现象
- ✅ 5 Whys方法找根本原因
- ✅ 多层验证（测试系统是否工作）

**避免的陷阱**:
- ❌ 简单归因（"数据不够"）
- ❌ 表面解决（"收集更多数据"）
- ❌ 假设验证不足（没测试系统）
- ❌ 重复犯错（Phase 3.1的错误方法）
